# Agents Knowledge (MonitorDocs)

This directory stores progress records, session snapshots, and lightweight artifacts generated by AI agents working on the MonitorDocs project.

Conventions
- Storage format: YAML files for human-readability and versioning.
- Required fields for a progress YAML record:
  - `date` (ISO string)
  - `agent_id` (string)
  - `summary` (short text)
  - `artifacts` (list of file paths)
  - `tags` (list of tags)

Directory layout
- `logs/` — YAML progress entries (committed)
- `sessions/` — session snapshots for interactive agent sessions (committed)
- `models/` — large model binaries (git-ignored)
- `notes/` — freeform notes (committed)
- `metadata/` — small JSON/YAML metadata (committed)

Sessions
- Purpose: store snapshot records of interactive sessions (planning, scaffold runs, CI runs).
- Location: `sessions/` — each session is a YAML file named with a timestamp (e.g. `2026-04-25-session.yaml`).
- Schema (recommended keys):
  - `session_id`: unique identifier (string)
  - `date`: ISO datetime
  - `participants`: list of participants (agents, users)
  - `summary`: short overview
  - `actions`: ordered list of steps performed
  - `files_changed`: list of workspace-relative paths
  - `artifacts`: list of artifact paths (do not commit large files themselves)
  - `tags`: list of tags

How to save a session (manual)
- Create a YAML file in `sessions/` using the schema above and commit it to the repo.
- Keep large artifacts out of the repository; reference them by path or external storage.

Example session: see `sessions/current-session.yaml` for a sample of the current work session.

Keep large binaries out of the repo (see MonitorDocs/.gitignore).
